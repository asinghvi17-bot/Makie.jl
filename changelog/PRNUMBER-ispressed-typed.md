## Changed

- `ispressed` is now a single method that branches on the type of the button (`Bool`, `Keyboard.Button`, `Mouse.Button`, `And`, `Or`, `Not`, `Exclusively`, and `Tuple`, `Vector` and `Set` of those) instead of one method per type. A button read from an `Observable{IsPressedInputType}` or an `Any`-typed attribute is therefore a call with a single candidate method, which type inference returns as `Bool`. This removes the dynamic dispatch on `ispressed` that ahead-of-time compilation (`juliac --trim`, WasmCodegen) cannot compile. A `Vector` or `Set` whose element type is one of those of buttons or of operators of buttons (`Keyboard.Button`, `Mouse.Button`, `Union{Keyboard.Button, Mouse.Button}`, `Enum{Int32}`, `Bool`, `Any`, `BooleanOperator`, `Exclusively` and `And`, `Or`, `Not` of the two button types) is found by `isa` and iterated with its concrete type, also when read from an `Observable{IsPressedInputType}` or `Any`. That makes the iteration of the collection static; the elements of a `Vector{Any}` or `Vector{BooleanOperator}` can still be nested or custom values that need dispatch a static build can't compile. Collections are iterated as before, whatever their element type: there is no change in behaviour for collections themselves. Other element types go through the internal `Makie._ispressed_collection_fallback`, the one dynamic call that is left. WasmCompat's Makie extension replaces it in a Wasm build (it relies on that name and signature): an empty collection is `true` as natively, and any other collection of such a type throws an `ArgumentError` naming the type. The behaviour changes that come with the single method:
  - A button type that `ispressed` does not know, also one inside an `And`, `Or`, `Not` or a collection, now throws an `ArgumentError` instead of a `MethodError`.
  - Elements of operators and collections that are not one of the types above are evaluated with `ispressed(parent, element, waspressed)`, so methods that are added to `ispressed` for other types keep working there, and must accept the `waspressed` argument. Methods that are added for the types above (e.g. a method for `Keyboard.Button` or `Vector{Keyboard.Button}`) are still used when `ispressed` is called with that type directly, but are no longer used for elements of operators and collections.
  - `ispressed(parent, Exclusively(...), waspressed)` with a button as `waspressed` no longer errors.
