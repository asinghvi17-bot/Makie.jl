## Changed

- `ispressed` is now a single method that branches on the type of the button (`Bool`, `Keyboard.Button`, `Mouse.Button`, `And`, `Or`, `Not`, `Exclusively`, and `Tuple`, `Vector` and `Set` of those) instead of one method per type. A button read from an `Observable{IsPressedInputType}` or an `Any`-typed attribute is therefore a call with a single candidate method, which type inference returns as `Bool` (`Base.return_types`). This removes the dynamic dispatch on `ispressed` that `juliac --trim=safe` and WasmCodegen cannot compile. It does not yet make every call site compile statically, checked with a strict WasmCodegen compile (`verify = :error`, `trim = :safe`, WASI): see the last item. The behaviour changes that come with this:
  - A button type that `ispressed` does not know, also one inside an `And`, `Or`, `Not` or a collection, now throws an `ArgumentError` instead of a `MethodError`.
  - Elements of operators and collections that are not one of the types above are evaluated with `ispressed(parent, element, waspressed)`, so methods that are added to `ispressed` for other types keep working there, and must accept the `waspressed` argument. Methods that are added for the types above (e.g. a method for `Keyboard.Button` or `Vector{Keyboard.Button}`) are still used when `ispressed` is called with that type directly, but are no longer used for elements of operators and collections.
  - `ispressed(parent, Exclusively(...), waspressed)` with a button as `waspressed` no longer errors.
  - Static compilation (`juliac --trim=safe`, WasmCodegen) compiles `ispressed` for these types of the button where it is called: `Bool`, `Keyboard.Button`/`Mouse.Button`-based `And`, `Or` and `Not`, `Exclusively` (before, it failed on hashing the `Set` of the two enum types), `Tuple`, `Vector{Keyboard.Button}`, `Vector{And{...}}` and `Set{Union{Keyboard.Button, Mouse.Button}}`, with an `Events` or a `Scene` as parent, and with the `waspressed` argument. It does not yet compile when the button is read as `IsPressedInputType` (`Observable{IsPressedInputType}`) or `Any` (an attribute), or for a `Vector{Any}` or `Vector{BooleanOperator}`: a `Set` of an unknown element type can be reached there, and iterating it is a dynamic call. The dynamic dispatch on `ispressed` itself is gone in all of these, only the iteration of that `Set` is left.
