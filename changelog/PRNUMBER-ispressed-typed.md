## Changed

- `ispressed` is now a single method that branches on the type of the button (`Bool`, `Keyboard.Button`, `Mouse.Button`, `And`, `Or`, `Not`, `Exclusively`, and `Tuple`, `Vector` and `Set` of those) instead of one method per type. A button read from an `Observable{IsPressedInputType}` or an `Any`-typed attribute is therefore a call with a single candidate method, which `cam2d!`, `Axis`, `Axis3`, `Camera3D` and `DataInspector` need for ahead-of-time compilation (`juliac --trim`, WasmCodegen). The behaviour changes that come with this:
  - A button type that `ispressed` does not know, also one inside an `And`, `Or`, `Not` or a collection, now throws an `ArgumentError` instead of a `MethodError`.
  - Elements of operators and collections that are not one of the types above are evaluated with `ispressed(parent, element, waspressed)`, so methods that are added to `ispressed` for other types keep working there, and must accept the `waspressed` argument. Methods that are added for the types above (e.g. a method for `Keyboard.Button` or `Vector{Keyboard.Button}`) are still used when `ispressed` is called with that type directly, but are no longer used for elements of operators and collections. Collections of any other element type (`Vector{And{...}}`, a `Union`, an empty `Set{Union{}}`, ...) are still evaluated element by element, but are only statically compiled when the type of the collection is known where `ispressed` is called, and not when it is read from an `Any` or `IsPressedInputType`. Collections with `Keyboard.Button`, `Mouse.Button`, `Enum{Int32}`, `Union{Keyboard.Button, Mouse.Button}`, `BooleanOperator`, `Bool` or `Any` elements are always statically compiled.
  - `ispressed(parent, Exclusively(...), waspressed)` with a button as `waspressed` no longer errors.
